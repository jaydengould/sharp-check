# Novig (phase 9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Novig as a third venue: money-level own-money P&L, bankroll and reconcile for all activity, plus per-bet tracking of cash-funded straights.

**Architecture:** Same pipeline as the other venues: signed read-only client → `raw_pages` → `normalize.rebuild` → existing tables → metrics/app. Ledger rows the API can't tie to a visible fill or position become `cash_ledger` kind `untracked_bet`.

**Tech Stack:** Python 3.12, requests, cryptography, SQLite, Dash.

**Spec:** `docs/superpowers/specs/2026-11-17-novig-design.md`

## Global Constraints

- Read-only: only `GET` on `https://api.novig.com`. Env `NOVIG_READ_KEY_ID`, `NOVIG_READ_PRIVATE_KEY` only. No management key, no POST.
- Never print keys, key IDs, signatures, response headers or amounts.
- Money as integer micro-dollars, timestamps `iso_us` UTC. Novig `ts` fields are epoch ms.
- Fixtures scrubbed: key IDs, transaction IDs, ref and all money fields replaced with fakes.
- Novig is excluded from CLV, spread (8a) and line shop (8b).
- Work on the local `novig` branch; no push.

## Review Focus

1. A Novig 451 (location check) during sync: Kalshi and Polymarket still archive; the run prints a Novig failure and exits non-zero.
2. More than one wallet in a key-ID envelope (a subaccount appears): fail loudly, never mix wallets.
3. A ledger kind not in the map (ADJUSTMENT, TRANSFER_*, CREDIT_RECLAIM, new): the rebuild fails naming the kind.
4. A Novig bet reaching the Kalshi/PM-only paths (`sync_closes`, `sync_line_shop`, `spread_costs`) would call the wrong venue's API: every one excludes `novig`.
5. A market with ≠ 2 outcomes: the rebuild fails.

### Task 3: Normalize

**Files:** Modify `sharp_check/normalize.py`, `sharp_check/classify.py`. Test `tests/test_normalize.py`, `tests/test_classify.py`.

**Interfaces — Consumes:** raw_pages from Task 2. **Produces:**
- `classify.novig_type(market_type: str) -> str` in `moneyline|spread|total|prop|future|other`; `_PROTECTED` suffix stripped first; unknown → `other` (printed by `__main__` like other codes).
- `novig_fills(conn)`, `novig_cash(conn)`, `novig_settlements(conn)`, `novig_games_markets(conn)` wired into `rebuild`.
- `novig_check_pnl(conn)`: each settled novig bet's `realized_pnl` vs `/v3/history/positions` `pnl` (latest page per positionId) within 10_000 micros, else `ValueError`.
- `spread_costs` skips novig fills (no `fill_costs` rows).

Rules (from the spec): outcome = `yes` iff outcomeId = `outcomes[0]`; price = `micros(cost)/qty` rounded; fee `micros(fee or "0")`; ts `iso_epoch(ts/1000)` via ms; markets with ≠ 2 outcomes → `ValueError`. `yes_value`: WIN → ONE, LOSS → 0, decimal string → micros, PUSH (a refund) → derived from the user's settled position: `payout / qty` on that position's outcome, mapped to the YES side (`ONE − x` if it held outcomes[1]). This makes it a void bet with the venue's actual payout. A PUSH market with no position row → `ValueError`. Ledger: DEPOSIT → deposit, WITHDRAWAL → withdrawal; FILL/FEE/MAKER_CREDIT with `ref` in visible fillIds and SETTLEMENT with `ref` in visible positionIds → skipped; other FILL/FEE/SETTLEMENT and FORWARDING/CREDIT → `untracked_bet`; anything else → `ValueError`. Settlements: markets with status SETTLED; `settled_ts` from `settledTs` ms. Games: `novig:<eventId>`, league, event description, `startsTs`.

- [ ] Step 1: tests on the fixtures: `test_novig_fills_normalize`, `test_novig_ledger_kinds` (visible FILL/SETTLEMENT skipped, FORWARDING/CREDIT/unmatched FILL → untracked_bet, ADJUSTMENT raises), `test_novig_market_two_outcomes_only`, `test_novig_settlement_and_pnl_check` (mismatched pnl raises), `test_novig_type_map` (`SPREAD`→spread, `RECEPTIONS_PROTECTED`→prop, `TOP_TEN_FINISH`→future, `TEAM_TOTAL`→other, `MONEY`→moneyline).
- [ ] Step 2–4: FAIL → implement → PASS (`python -m pytest tests -q`).
- [ ] Step 5: commit.
